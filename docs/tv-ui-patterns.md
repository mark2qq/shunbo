# 电视直播软件的界面范式与可复用实现思路

> 用途：作为顺播 UI 重构的设计基线。回答两件事——**主流产品是怎么做的**、
> **在 Flutter 里怎么低成本做到**。第 6 节是「本项目怎么落地」，改界面之前先看这里。

---

## 1. 三种主流布局范式

### A. 全屏 EPG 网格（机顶盒范式）
代表：TiviMate、传统有线机顶盒、Kodi PVR。

- 进入即全屏节目单：左侧固定频道列，右侧横向时间轴，每格是一个节目。
- 当前频道在角落以 PiP 小窗继续播放，**浏览不打断观看**。
- 遥控器右滑展开时间轴，左滑回看（配合 catch-up）。
- 优点是信息密度最高、最"电视"；缺点是首次进入看不到大画面，且 EPG 数据缺失时整屏是空的。

### B. 分区 Dashboard（App 范式）
代表：IPTV Smarters、奇异果 TV、多数国产电视 App。

- 首屏是 4 个入口宫格：直播 / 电影 / 剧集 / 回看。
- 进直播后是「分类 tab + 频道列表」，选中即播。
- 优点是好理解、无 EPG 也能用；缺点是层级多一跳，且首屏不是画面。

### C. 侧栏 + 预览（混合范式）
代表：央视影音、部分运营商 IPTV、本项目选型。

- 顶部/侧边固定栏目（直播、电影、电视剧、纪录片），默认进直播。
- 直播页 = 大画面 + 常驻频道栏；换台只换流，不换页面。
- 优点：**首屏即有画面**（满足"打开即看"），同时保留分类扩展能力；
  缺点是画面与列表要抢空间，需要响应式规则（见 §4）。

### 选型结论

本项目要满足「默认进直播且直接出画面」+「多栏目扩展」，只能选 **C**，
并把 A 的 EPG 作为直播页的**第二视图**（切过去才占满屏），而不是首屏。

## 2. 频道分类与切换

| 模式 | 做法 | 代价 |
|---|---|---|
| 分组折叠树 | 央视 / 卫视 / 地方 / 专题，组内频道网格 | 需要分组元数据；M3U 的 `group-title` 直接可用 |
| 分类 Tab | 顶部横向 tab，点击过滤 | 组多时 tab 溢出，需要横向滚动 |
| 数字直达 | 遥控器输入频道号 | 需要稳定的频道编号分配策略 |
| 上/下切换 | 播放中按上下键换相邻台 | 必须与列表滚动方向一致，否则"按上却跳到下面的台" |

可复用要点：
- 频道 id 必须**稳定且跨索引一致**（用台名归一化，不要用数组下标），否则换源/刷新后收藏与当前台全丢。
- 换台要**去抖 + 世代号**：快速连点时只让最后一次调台生效（本项目 `LiveController._epoch`）。
- 换台不要重建页面，只换播放地址；页面重建会闪一下黑屏。

## 3. EPG 节目单与预告

数据源标准是 **XMLTV**（`<channel>` + `<programme start/stop>`），
IPTV 侧通常由 provider 提供 XMLTV URL 或 Xtream Codes 接口下发。

可复用实现：
1. **数据**：解析 XMLTV → `Map<channelId, List<Programme>>`，按时间排序；
   `channelId` 用 `tvg-id` 对齐（M3U 的 `tvg-id` 与 XMLTV 的 `channel id` 同源）。
2. **视图**：左侧频道列 + 右侧时间轴，两列**共用同一个 `ScrollController`** 的垂直偏移，
   横向时间轴单独一个 controller；节目块宽度 = `时长 × 每分钟像素`。
3. **现在/下一档**：列表态每个频道只显示 `now` 与 `next` 两行，成本极低、信息够用。
4. **降级**：EPG 缺失时不要留白格，直接显示"节目信息暂缺"，并用频道名占位——
   空网格比没有网格更让人困惑。
5. **时间基准**：一律存 UTC 秒，渲染时才转本地时区；跨时区/夏令时全靠这一步。

## 4. 收藏、历史、搜索

- **收藏**：单独持久化一组 channel id（顺序即排序），列表顶部固定「我的收藏」组。
  长按 OK 加入/移出是电视端惯例（TiviMate 就是长按）。
- **历史**：记录「最近观看」的 channel id + 时间戳，保留最近 N 条（20~50），
  与收藏分开存——收藏是意图，历史是行为，混在一起会互相污染。
  点播侧的历史要存**内容坐标**（本项目已有 `ResumeRecord`），直播只存频道。
- **搜索**：电视端不要给输入框当主入口（遥控器打字是灾难）。
  首选「首字母/拼音过滤 + 方向键选择」，退一步用系统语音输入。
  搜索范围要覆盖频道名、当前节目名、点播片名。

## 5. 画质与线路切换、焦点导航

### 线路切换
- 同一个台维护多条线路（`qualityRank` 降序），**失败自动降级**是默认行为，不需要用户干预。
- 手动切换入口放二级（长按 OK / 详情面板），列「线路 1 · 高清 / 线路 2 · 标清」。
- 切换后必须**保持播放位置**（直播无位置，但要保持"仍在同一台"的语义）。

### 多源与无感换源（本项目重点）

「一个台一个源」在公开信号上是不成立的：源会限流、会挂、会「连得上但 20 秒不出画面」。
主流直播软件的做法不是「求一个稳定的源」，而是**同一台备多条源 + 自动挑最快的那条**。

四个可复用的设计点：

1. **多源从哪来**
   - 通用的 M3U 索引（iptv-org 这类）**每个台只给一条流**——实测中文索引 150 个台
     只有 150 条流。真正有多线路的是同一数据集的 `streams.json`（CCTV-1 有 4 条、
     深圳卫视 12 条）。两表用 `tvg-id` 关联（注意索引里的 `CCTV1.cn@SD` 要剥掉 `@SD`）。
   - 换源不能只靠「同一份索引再拉一遍」：要多拉几份索引并**合并**，
     代码里 `break` 掉后续索引等于主动放弃备用源。

2. **按什么排序**
   - 排序键：`失效(排最后) > 高清档 > 健康分 > 画质 > 原始顺序`。
     高清档压过健康分是「加载频道时首先加载高清线路」的硬要求：
     不能因为某条标清线路探测更快就先播标清。
   - 健康分 = 探测延迟 + **起播延迟** + 失败次数。起播延迟权重最高，
     因为用户感知的是「点下去多久出画面」。
   - **只有探测数据、没有起播数据的线路必须压分**：实测某源探测 138ms、
     起播 17.3 秒。只按探测排序会一直选中那条最慢的，用户体感「换了反而更卡」。

3. **怎么做到切换平滑**
   - 换线时若该线路 5 分钟内实测可用，**跳过探测直接交给内核**——省掉 3~4 秒等待
     （窗口不能太长：公开源几十秒内就可能变成 403/404）。
   - 播放稳定后**在后台预热**本台其余线路（只探测，不碰播放器），下次换线不必现场测。
   - 有多条线路时缩短起播耐心（30s → 15s）：等太久不如早点换一条。
   - 换线失败不要弹错误页：静默换下一条；**该台所有线路都试过仍不能播 → 按频道表顺序自动切下一个台**，
     走与用户手动点台完全相同的起播流程。绝不原地反复重连、也不留在 `tuning`。
     一轮全表扫完仍全灭才落到明确 `failed` 终态，并 30 秒低频重扫（不空转）。
   - 状态行常驻「线路 2/4 · 起播 3.8s」，让用户知道「有几条源、现在用的哪条」。

4. **健康度要持久化**
   - 落盘 `live-health.json`（原子写），下次冷启动直接选「已知最快」的源。
   - 失效记录带 10 分钟有效期：长期拉黑会让恢复的源永远回不来。

### 遥控器焦点导航（Android TV 官方要求）
- 所有交互元素都必须可达、可聚焦，且有**统一的焦点态**（描边 + 轻微放大 + 高亮）。
- 启动后与空闲时**必须有一个元素处于焦点**，否则用户第一下按键没有反馈。
- 方向键在列表上要能滚完整个列表；滚动时焦点项要 `ensureVisible`。
- 返回键行为可预测：先退焦点到侧栏 → 再退出页面 → 最后回系统桌面；
  **不要在屏幕上画返回按钮**，也不要给退出加二次确认。
- 电视安全边距 5%（过扫描），重要 UI 不要贴边。
- 10 英尺 UI：正文不小于 13~14px，标题 18px+，高对比度。

Flutter 侧实现：
- `FocusTraversalGroup` + `FocusNode` + `Shortcuts/Actions` 接管方向键；
- 焦点态用 `AnimatedContainer` 改 `border` 与 `scale`，不要用 `InkWell` 的 hover 态糊过去；
- 列表滚动配 `Scrollable.ensureVisible(context, alignment: 0.4)`；
- 快捷键绑定集中在一处（`Shortcuts` 包住页面），不要散落在每个 widget。

## 7. 本轮实测踩到的坑（都在真机上复现过，值得写进规范）

这一节不是"设计模式"，是**血泪清单**。它们的共同点是：界面上看起来只是"黑屏"，
真实原因却在完全不同的一层。以后加功能时先对照这里，能省掉大量猜测。

| 现象 | 真实原因 | 规范动作 |
|---|---|---|
| 首屏黑屏，最后落到演示流 | 内置清单 31 个台全指向同一个**已关停**的镜像，它们占满了"并发探测 8 个"的窗口，能播的远端频道一条都轮不到 | 探测**分批进行**，每轮把死主机记下来，下一轮自动跳过；硬编码的直播地址一律不留 |
| 界面显示"暂无信号"，画面其实在动 | 直播的时间轴要等稳定后才推进，用 `position > 0` 判起播会把正在播的流判死 | 直播起播判定用「位置前进」**或**「新流出了画面」；后者的判据是**视频参数世代号变大**，不是宽高值 |
| 换台后"秒出画面"，其实还是上一个台的最后一帧 | 同分辨率切换时内核宽高不变，`hasPicture` 在 load 前后都是 true | 同上：只认"收到新的视频参数"这个事件 |
| 正在正常播放的台，18 秒后自己跳台 | 看门狗把"位置不前进"当卡死，而直播的 `buffering` 长期为 true | 位置为 0 时用"有画面"兜底，且**不要求**"不在缓冲" |
| 截图里"频道栏消失了" | 截图进程 DPI 不感知，屏幕 2880×1800 被当成 1440×900，`GetDC` 只截到左上四分之一 | 截图/度量工具先 `SetProcessDpiAwarenessContext(-4)`；`tooling/capture_screen.dart` 已内置 |
| 频道栏真的在屏幕外 | 窗口尺寸被 DPI 放大到 2560×1440，超出可用区域 | 电视式布局默认最大化，且在**首帧之后**最大化（`Show()` 用 SW_SHOWNORMAL 会撤销提前的最大化） |
| 片库"有内容"却一集都放不出来 | 全部地址指向一个在本网络下 **DNS 解析失败**的桶 | 换片源必须实测可达（`tooling/check_vod_sources.dart`），死链比没有更糟 |
| 频道栏台标整列都是「CCTV」 | 台标取台名前 4 个字，央视台名前 4 个字完全相同 | 央视台标只留频道号（`1` / `13` / `5+` / `4K`） |
| 「补了备用源」但每个台还是只有 1 条线路 | M3U 的 `tvg-id` 带 `@SD`/`@HD` feed 后缀，`streams.json` 的 key 没有，一条都对不上 | 关联前先剥 `@` 后缀（`normalizeTvgId`） |
| 换线后反而更卡 | 探测 138ms 的源被排到第一，实际起播 17.3 秒——探测只测「第一个数据块」，测不到起播 | 没有起播数据的线路分数设上限（≤78），不让它压过已验证线路 |
| 点「换线路」先卡一轮才换成功 | 简单取「下一条」，正好是刚被判定失效的那条 | 换线选择跳过失效线路；全失效才退回下一条 |

一句话总结这些坑：**"能连上"不等于"能播"，"有数据"不等于"有画面"，
"界面对了"不等于"用户看得见"**。三层都要有独立的、可观测的判据。

## 8. 分类栏 / 城市定位 / 控制条（2026-11-06 改版）

### 交互约定

- 分类固定 11 项：**全部 → 央视频道 → 卫视频道 → 地方频道 → 新闻 / 体育 /
  影视 / 少儿 / 纪实 / 生活 → 其它频道**。刻意不从当前频道表反推——
  那样某个分类暂时没数据就会整个消失，少儿、其它这类靠后的分类再也找不到入口。
- 三条切换路径：分类条**两端箭头**（遥控器 / 鼠标）、频道区**左右滑动**
  （触屏 / 主流播放器手势）、分类条上的**鼠标滚轮**。选中分类自动
  `Scrollable.ensureVisible` 滚进可视区。
- 频道列表始终 `Expanded` + `Scrollbar(thumbVisibility: true)` + `ListView.builder`，
  长列表完整可达。
- 只有「地方频道」分类下才出现城市选择器；默认 = **用户上次选择 > IP 定位 >
  全部城市**。定位城市没有收录频道时退回「全部城市」并提示，且该城市仍留在下拉里
  （避免「为什么没有我所在的城市」）。未识别城市的台统一收在「其它城市」，
  不会因推断失败而彻底消失。

### 数据层

- `satelliteAliases` 把 `Hunan TV` / `Jiangsu Satellite TV` 归一成中文「XX卫视」，
  与国内索引的中文台名算出同一个 id → 合并成多线路。只收**主频道全名**，
  `Hunan News Channel` 这类地面频道不命中。
- 中文 `group-title`（卫视频道 / 浙江频道 / 内蒙频道）显式映射；
  `XX频道` 统一归「地方频道」。
- 购物台在 `parseM3U` 阶段就不建频道对象，并在 `load()` 的所有返回路径
  再过一次 `withoutShopping`——是「从列表移除」，不是仅隐藏。
- 国内补充索引排在三份索引**最后**：它的流是 IPv6 直连地址，放后面才能保证
  优先走 iptv-org 的可达线路，不拿死链去撞首屏探测窗口。
- **城市台补充索引**单独装配（`citySupplementUrls`，不混进 `kDefaultLiveIndexUrls`）：
  三份主索引实测**一个苏州台都没有**，而 IP 定位默认城市正是这类地市台。
  补充表有 1600+ 条（多数是央视/卫视重复线路与省级台），因此 `parseM3U` 增加
  `cityOnly` 只放行「台名能推断出城市」的条目，并放宽扫描上限——城市台在这份表
  里排在第 600 条 `#EXTINF` 之后（苏州在第 1448 行），沿用默认 600 条上界会被全截掉。
  过滤发生在计数之前，被丢掉的条目不占额度；补充源挂了完全静默，不写 warning。
  结果：地方频道 61 → 160 台，可切换城市 15 → 53 个，苏州 5 台。

### 本轮新增的坑

| 现象 | 真实原因 | 规范动作 |
|---|---|---|
| 卫视频道几乎是空的 | iptv-org 把卫视写成 `Hunan TV` / `Jiangsu Satellite TV`，老逻辑只认中文「卫视」 | 英文台名归一成中文标准名再算 id，顺带把两份索引的线路合并 |
| 桌面端「少儿 / 其它」点不到 | 鼠标滚轮给的是纵向 delta，横向 `ListView` 默认完全不响应 | 把 `scrollDelta.dy` 换算成分类栏横向偏移；再补两端箭头与滑动手势 |
| IP 定位拿到乱码、功能失效 | pconline 中文字段是 GBK，且 GBK 第二字节可能是 `0x5C`，会把 JSON 字符串错误转义 | 用纯 ASCII 的 `cityCode` 定位；`parseCityBytes` 先从 Latin-1 字节视图抠码，再退回 UTF-8 文本解析 |
| 「苏州市」被解析成空串 | 先去省份前缀的正则 `^XX(省\|市)` 会把「苏州」+「市」整个吃掉 | **先去行政后缀，再去省份前缀** |
| 襄阳被识别成西安 | 拼音 `xian` 是 `xiangyang` 的前缀 | 拼音关键词按长度降序、只在台名开头匹配；中文关键词全串匹配优先 |
| 控制条又多了一行、变高 | 「换线路 / 刷新」原来独占上面一行 | 并进核心行（按用户红框标注），取消次级行，展开态高度 112 → 82 |
| IP 定位到苏州，地方频道却显示「全部城市」 | 三份公开索引一个苏州台都没有，`defaultCity` 按设计退回全部城市 | 增加城市台补充索引；不能只加 URL——苏州在第 651 条之后，会被 600 条上界截掉，必须 `cityOnly` + 放宽上限 |
| 补充索引一接上，频道表被重复线路灌满 | 该表 1600+ 条里绝大多数是央视/卫视的多条线路 | 只保留能推断出城市的条目，输出从千级降到百级；主索引全失败时仍退回内置清单 |

**定位结果只有命中 `CityDirectory.isKnown` 才被采纳**：定位接口返回的任意字符串
不会流进 UI 标题或落盘文件，脏数据最多让功能退回「全部城市」。

## 9. 全网检索 / 高清优先 / 自动切台（2026-11-06 第三轮）

### 9.1 检索源要「显式建模」，不要散落成一串 URL 常量

`LiveSourceDescriptor` 把每份源写成 `(URL, 格式, 范围, 体积上限, 扫描行数, 条目上限, 标签)`：

| 范围 | 用途 | 为什么必须收窄 |
|---|---|---|
| `cityOnly` | 只留能推断出城市的台 | 城市补充表 1600+ 条，绝大多数是央视/卫视重复线路 |
| `chinaOnly` | iptv-org 全球总索引只留中国条目 | 1.1 万条境外频道会把央视卫视挤出首屏、占满探测窗口 |
| `hdOnly` | 4K/高清专表 | 只收 `qualityRank >= 70`，避免用标清线路稀释高清覆盖 |

格式分 `m3u` 与 `nameUrl`（国内 `台名,地址` + `#genre#` 分节）。苏州台刻意准备了
**两台不同主机镜像 + 两种格式**，单份源挂掉/格式解析规则变动时仍能稳定收录。
**过滤必须发生在计数之前**，否则被丢掉的条目会占掉 `channelLimit` 额度——
苏州在补充表里排在第 1448 行，这正是上一轮踩过的坑。

### 9.2 分类推断要区分「明确规则」和「兜底猜测」

全网扩展后真实探针显示「其它频道」被 376 个中文地方台冲爆（`徐州-1`、
`上虞1新闻综合`、`Xinjiang TV 1`…）。归类顺序固定为：

```
台名归属(CCTV/CGTN/CETV/卫视) → group-title 映射 → 台名栏目词
→ 中文台名 / tvg-id 国家码(.cn/.tw/.hk/.mo) → 地方频道 → 其它频道
```

**关键陷阱**：频道 id 用「分组 + 台名」归一化。原实现只在展示分组为
「其它频道」时才把原始 `group-title` 当身份前缀；中文兜底改成「地方频道」后，
`A组/同名台` 与 `B组/同名台` 会算出同一个 id 被合并（点 A 播到 B 的流）。
修法是新增 `explicitGroupOf()`，只有**兜底推断**（返回 null）且非卫视归一分支时，
才用原始分组作身份前缀。修完其它频道 376→11、地方 161→404、少儿 9→17。

### 9.3 高清优先要三处同时收口

只改解析器的画质词不够：备用源是另一条链路补进来的，会把标清线路又插到前面。

1. `parseStreamIndex()` / `withBackupStreams()` 按画质降序补入；
2. `normalizeStreams()` 在 `load()` **装载末尾**统一去重 → 高清在前 → 单台封顶 10；
3. `LiveSelection.rankStreams(preferHd: true)` 播放排序把高清档放在健康分之前。

实测 706 台 / 1248 条线路 / **244 台有高清线路（362 条）**，`CCTV-1` 的 5 条线路
画质序列为 `[90, 90, 70, 60, 60]`。

### 9.4 失败切换的状态机与闪退根因

旧实现「同一台静默重连 2 次」正是用户反馈的「反复加载、卡在加载状态」。新链路：

```
该台所有线路试完 → phase = failed（明确终态，不是 tuning）
  → 800ms → tune(next, manual: false)   // 与手动点台完全相同的流程
  → 出画面则清空本轮轨迹；否则继续按频道顺序跳
  → 一轮扫完 → failed + 30s 低频重扫（清空失效登记，不紧循环）
```

**闪退根因不是 Dart 异常，而是并发 `player.load()`**：`_epoch` 只能丢弃过期结果，
挡不住已经发出的原生调用。所有会碰播放内核的流程（tune / failover / pause / stop）
一律经 `AsyncSerialGate` 排队；再叠加 Timer 回调 try/catch、`_tryStream()` 整体吞异常、
`_notify()` 的 dispose 守卫、看门狗 `_failoverInFlight` 防重入。

回归环境上还有一条工程经验：`package:flutter/foundation.dart` 顶层依赖 `dart:ui`，
裸 `dart run` 连 `LiveController` 都 import 不进来（`'Picture' isn't a type`）。
用条件导入 `if (dart.library.ui)` 在回归里换成最小 `ChangeNotifier` 替身，
Flutter 构建仍走官方实现，才能写出**真实控制器状态机**回归（23/23）而不只是源码静态检查。

### 9.5 本轮新增的坑

| 现象 | 真实原因 | 规范动作 |
|---|---|---|
| 全网索引一接上，其它频道从 40 涨到 376 | 大量地市台没有 `group-title`，旧逻辑一律落「其它频道」 | 中文台名 / tvg-id 国家码兜底到「地方频道」，台名栏目词先分内容栏目 |
| 同名台被合并成一条，点 A 播到 B | 兜底分组都变成「地方频道」，id 前缀撞车 | 身份分组只在兜底推断时保留原始 group |
| 高清线路仍不是第一条 | 备用源链路按原序补入，绕过了解析器的画质排序 | 装载末尾统一 `normalizeStreams` 收口 |
| 快速换台 / 失败切换时偶发闪退 | 多个异步流程并发调用原生 `open` | `AsyncSerialGate` 串行化；epoch 只用于丢弃过期的**结果** |
| 回归脚本无法 import 控制器 | `foundation.dart` 拉进 `dart:ui` | 条件导入 + 纯 Dart 最小替身 |
| 门禁输出把内核日志误判成失败 | `debugPrint` 里的 `Failed to open` 等噪声 | 替身的 `debugPrint` 静默，门禁只认 `FAIL` 前缀 |

### 10.1 问题

## 11. 频道分类来源策略 + 数字编号 + 遥控器按号跳台（2026-11-06）

### 11.1 分类是「可叠加」的，不是一台一个分类

原来的 `group` 是一台一个：既是央视又是新闻台的频道只能二选一，用户在
「新闻」分类里看不到央视的新闻台，在「央视频道」里又分不出它是新闻。

现在拆成两层：

* **主分类**（按来源归属）：央视 → 央视频道；卫视 → 卫视频道；地方 → 地方频道；
  全网其它视频源 → 其它频道（只有「纪实」例外，见下）。
* **内容分类**（按栏目）：新闻 / 体育 / 少儿 / 影视 / 生活 / 纪实。

一个频道可以同时属于两者，频道栏过滤用的是**并集**
（`LiveChannel.categories` + `LiveChannel.inCategory`）。

### 11.2 来源归属的判定顺序

`ChannelTaxonomy.sourceOf(name, tvgId:, remoteGroup:)`：

1. **台名**：`CCTV-*` / `CGTN-*` / `CETV-*` / `央视` / `中国教育` → 央视；
   含「卫视」→ 卫视。
2. **远端 group-title**：国内聚合表直接写「📺央视频道」「📡卫视频道」
   「☘️江苏频道」，比台名更可靠（`综合频道` 这种台名单看完全判不出归属，
   但它挂在「央视频道」分节下）。
3. **tvg-id 国家码**：`.cn` / `.tw` / `.hk` / `.mo` → 地方。
4. 兜底：全网其它视频源。

`WCETV`（美国台）里也含 `CETV`，所以央视正则前面必须留 `(^|[^a-z])`。

### 11.3 分类策略表（配置，不是散在解析器里的 if）

```text
新闻 / 少儿 / 体育 / 影视 / 生活 → 央视 + 卫视 + 地方
纪实                            → 央视 + 全网其它视频源
其它频道                        → 全网其它视频源
```

「全网其它视频源」这一档收的是境外台、来源标识不明的聚合条目。
按上表，境外新闻台**不进**「新闻」分类，而是落在「其它频道」——
这是需求原文「除上述已列来源之外的其它来源视频统一归入『其它』频道」的直接结果。

### 11.4 数字编号

| 号段 | 来源 | 说明 |
|---|---|---|
| 1–99 | 央视 | CCTV-1=1 … CCTV-17=17；CCTV-5+=18；CCTV 4K=19；CGTN=20；CGTN 纪录=21；**中国教育 1–4=22–25** |
| 101–199 | 卫视 | 按 GB/T 2260 省级行政区划顺序，北京=101 … 农林=135 |
| 201–899 | 地方 | 固定：苏州 201–205、南京 206–207、无锡 208–209、常州 210、杭州 211–212、上海 213–214；其余按台名稳定分配 |
| 901–999 | 全网其它视频源 | |
| 1001–1099 | 节目 | 点播条目 |
| 1101–1999 | 节目分集 | 1100 + 节目序号 × 10 + 集号 |

「稳定」靠两件事：号段由**来源**决定（与索引返回顺序无关）；首次分配即落盘
`channel-numbers.json`（键是归一化台名，与频道 id 无关），之后同一台永远同一个号，
索引新增台或换镜像都不会挤掉老号的号码。

**坑**：兜底分配（同名台出现两份时给第二份另找一个号）必须避开**前两轮全部已分配号**，
只避开「已按 id 用过的号」会让别的台抢走固定号——实测 `Ando TV` 抢走了苏州台预留的号，
把 `苏州新闻综合` 挤到 331。

### 11.5 遥控器按号跳台

* `HardwareKeyboard.instance.addHandler` 全局钩子（不要求控件先拿到焦点——
  遥控器操作时焦点往往停在画面上）。
* **逐位累积**：按 `1` 立刻切到 CCTV-1；1.5 秒内没继续按就按已输入的数字提交；
  确认键立即提交；返回键取消。
* 走的是与点台**完全相同**的 `LiveController.tuneByNumber → tune` 流程，
  不另开一条播放路径（否则「按号跳台」和「点台」会有两套失败处理）。
* 浮层放在**播放器舞台内部**：Windows 上视频是引擎合成层，挂在舞台外面的浮层会被
  视频盖住（实测踩过）；放进舞台后与控制条同一层级，可见。
* 安卓清单：`leanback` / `touchscreen` / `gamepad` 三个 `uses-feature` 声明为非必需，
  并注册 `LEANBACK_LAUNCHER`，电视端才能安装并被启动器检索。

### 11.6 界面上的两处「不显示」

播放器顶部原来的状态行（`无信号 · 索引线路 · 93/383`）与底部控制条右端的来源说明
（`公开索引 + 内置（383 个频道 · 129 个台有备用源）`）已整体删除：
前者是调试信息、后者对电视观众没有意义，两处都只占地方不提供信息。


时序（策略不依赖 flutter，可裸 `dart run` 回归）：

```text
初始：visible=false ── 页面加载不渲染任何可见控件
鼠标进入 30px 热区 → visible=true（180ms 淡入）+ 启动 400ms 计时
  ├─ 400ms 内点击胶囊 → tap() 撤销计时 → 立即展开
  └─ 停留到 400ms    → onHoverElapsed() → 自动展开（保留原「悬停呼出」手感）
鼠标离开且未触发   → visible=false（淡出）+ 撤销计时 → 不误弹
```

展开态**不渲染热区**：否则 30px 覆盖层会吃掉侧栏最外侧的导航项、分类 chip 与列表
滚动条点击。收起入口改为栏内 `OnDemandCollapseButton`，只在鼠标停在栏上
（`_sideHovering` / `_railHovering`）时淡入，固定 40×40 占位不引起头部布局跳动。

### 10.3 左右一致的具体清单

- 同一个 `EdgeRevealHandle`，`EdgeSide.left/right` 只决定贴边、圆角方向与箭头方向；
- 同一套计时：初始展开 → 6 秒无操作自动隐藏 → 鼠标在栏上不收 → 离开 1.2 秒收起；
- 两侧 `open` 都重排一次 6 秒自动隐藏（键盘/触摸唤出、鼠标没跟进栏内时不会永远停留）；
- 两侧 `close` 都是独立入口（`_closeSide` / `_closeRail`），取消计时后显式收起；
- 两侧 hovering 都通过 `setState` 驱动按需按钮淡入；
- 全屏（影院）与窄屏分支都不渲染浮层，手柄不会出现在这些布局里。

### 10.4 实机走查与工具坑

- `build/edges_idle.png`：静止态两侧无控件；`edges_left_wide.png`：只有左缘按需淡入 `>`；
  `edges_hover_left2.png` / `edges_right_open.png`：左右各自展开且头部各出现收起箭头；
  `edges_after_leave.png`：移开后两侧重新收起、无残留控件，频道内容与状态栏不变。
- **`SW_RESTORE` 坑**：`capture_screen.dart` / `click_at.dart` 原本用 `ShowWindow(hwnd, 9)`
  把最大化窗口还原成 854 宽，直接掉进窄屏分支（底栏 + 上下布局），侧边控件根本不渲染，
  还会打断 hover 让 400ms 计时被取消。三个工具统一改成 `SW_SHOW(5)`。
- **换行符坑**：`live_page.dart` 是 CRLF、`app_shell.dart` 是 LF，多行源码静态断言在
  Windows 上会假失败；回归读取源码统一 `replaceAll('\r\n', '\n')`。
- **截图转换**：本机 `Add-Type -AssemblyName System.Drawing` 被安全策略拦截、也没有
  ImageMagick，新增纯 Dart `tooling/bmp_to_png.dart`（BGRA→RGBA，强制 alpha=255，
  支持 `--crop=x,y,w,h,scale` 放大边缘做像素级确认）。
